# 게임 관측 데이터 저장 설정

기존 통합 시트에 가져온 관측값을 보관하기 위한 별도 저장소입니다. 이 SQL은 게임 서버에 접속하거나 로그인·패킷 수집을 수행하지 않습니다. 기존 출입·명단·권한 테이블, 기존 인증 함수도 변경하지 않습니다.

입력 탭의 **게임 데이터** 영역에서 해석된 JSON을 미리 보고, 관리자가 이 SQL을 적용한 뒤 운영진 공유 저장소에 보관할 수 있습니다. SQL 적용 전에는 미리보기·내보내기만 동작하고 공유 저장은 설치 안내를 표시합니다. 게임 자동 연결·실시간 수집·기존 편대 기록 자동 갱신은 아직 구현하지 않았습니다.

## 적용 전 필수 확인

저장소에는 운영 DB의 기존 인증 함수 정의가 포함되어 있지 않습니다. DB 관리자가 대상 Supabase 프로젝트에서 다음 사항을 먼저 확인해야 합니다.

- `public.get_editor_profile(p_name text, p_device_id text)`가 존재하고 단일 JSON 또는 JSONB 객체를 반환합니다.
- 반환 객체의 `device_status`가 실제 해당 편집자·기기의 승인 상태이며, 승인 상태를 기본값으로 만들어 내지 않습니다.
- `role`은 관리자일 때 `admin`, `perms`는 `entry` 또는 `*`를 포함할 수 있는 쉼표 구분 문자열입니다.
- 함수가 호출자의 기존 인증·편집자·기기 확인 규칙을 정확히 시행하는지 확인합니다. 공유 로그인 세션이나 클라이언트가 전달한 편집자 이름만으로 독립적인 사용자 신원 검증이 새로 생기지는 않습니다.
- `anon`, `authenticated` 역할과 `auth.role()`, `auth.uid()`가 있는 Supabase 환경입니다.
- 마이그레이션 실행자는 테이블과 RPC를 안전하게 소유하는 DB 관리자이며 브라우저용 역할이 아닙니다.

기존 인증 함수의 승인·권한 판별을 신뢰할 수 없으면 이 기능을 운영 DB에 적용하지 않습니다. 새 RPC에는 과거 프런트엔드의 기본 승인값이나 구형 권한 함수로 우회하는 경로가 없습니다.

## 적용 범위

검토할 파일은 `supabase/migrations/202611190001_game_observations.sql`입니다. 대상 프로젝트와 기존 인증 함수 정의를 확인한 뒤 DB 관리자가 Supabase SQL Editor 또는 기존 마이그레이션 절차로 한 번 적용합니다. 이 문서를 작성하는 과정에서는 운영 DB에 접속하거나 SQL을 적용하지 않았습니다.

추가되는 객체:

- `public.dw_game_observations`: 별도 관측 이력 테이블과 전용 인덱스·ID 시퀀스.
- `dw_game_observations_import(p_actor text, p_device_id text, p_rows jsonb)`.
- `dw_game_observations_list(p_actor text, p_device_id text, p_limit integer default 500)`.

테이블은 RLS를 켜고 직접 접근 정책을 만들지 않습니다. `PUBLIC`, `anon`, `authenticated`의 테이블·시퀀스 직접 권한은 철회합니다. 두 RPC만 `authenticated`에 실행 권한을 주며, RPC 내부에서도 인증 세션·명시적으로 승인된 기기·관리자 또는 `entry` 권한을 매번 확인합니다. 함수는 `SECURITY DEFINER`이며 조회 경로를 고정하고 테이블·인증 함수 이름을 명시합니다.

## 가져오기 데이터 계약

`p_rows`는 1~500개 객체의 JSON 배열이며 배열의 PostgreSQL JSONB 직렬화 크기는 최대 2 MiB입니다. 한 행이라도 유효하지 않으면 그 호출 전체가 실패하며 앞서 처리한 행도 저장되지 않습니다.

| 필드 | 형식 |
|---|---|
| `uid` | 필수 문자열. 숫자 6~20자리. 숫자형 UID는 거부 |
| `observed_at` | 필수 ISO 시각. 초까지 표기하고 `Z` 또는 `+09:00` 같은 시간대 명시. 소수 초 최대 6자리 |
| `source` | 필수 문자열. `get.new.user.info` 또는 `migrate.user.info`만 허용 |
| `name`, `alliance` | 선택 문자열. 각 최대 200자 |
| `server` | 선택 정수 |
| `total_power`, `migration_power` | 선택 정수 |
| `army_power`, `hero_power`, `building_power`, `science_power`, `pet_power`, `vehicle_power` | 선택 정수 |
| `kills`, `base_level` | 선택 정수 |

모든 숫자는 JSON 숫자이며 0~9,007,199,254,740,991 범위의 정수만 허용합니다. `1.2G`·`22억` 같은 표시 단위나 숫자 문자열은 받지 않습니다. 제공하지 않았거나 `null`인 선택 항목은 미확인으로 보관하며 0을 채우지 않습니다. 유효한 과거 관측 시각도 허용합니다. 모르는 필드가 하나라도 있으면 행을 거부합니다.

원본 패킷·로그인 응답 전체·토큰·쿠키·비밀번호·서명·QR 인증값·인증 헤더는 입력하지 않습니다. 이러한 별도 키는 허용 목록에 없어 거부됩니다. 문자열 안에 숨긴 인증값까지 식별하는 기능은 아니므로 가져오기 파일 자체에 필요한 표시·수치 필드만 남겨야 합니다.

관측 원본을 위 필드로 정리하는 과정에서 값과 출처를 추정하지 않습니다. `army_power`는 병력 구성 투력이며 F1 투력으로 사용하지 않습니다. F1·F2·F3 필드는 이 계약에 없으며 확인될 때까지 채우지 않습니다. UID와 기존 시트 구성원의 관계도 자동으로 추론하거나 기존 명단을 덮어쓰지 않습니다.

두 출처는 공식 클라이언트 정적 분석에서 확인한 명령 이름입니다. 허용 목록에 있다는 사실이 현재 계정의 실제 응답·실시간 수집 성공을 증명하지는 않습니다. 게임 API 호출·계정 연결·자동 갱신은 이 저장 기능의 범위가 아닙니다.

## 중복과 조회

- 동일 UID·관측 시각·출처와 동일한 표시/수치 내용은 중복입니다. 선택 항목의 생략과 `null`, 숫자의 정수 표기 차이는 같은 내용으로 처리합니다.
- 시각은 실제 시간으로 비교하므로 같은 순간의 `Z`와 시간대 오프셋 표기는 중복입니다.
- 같은 시각이어도 내용이 다르면 별도 관측으로 남깁니다. 기존 관측을 수정하지 않습니다.
- 내용은 검증된 필드만 정규화해 내장 `md5`로 지문을 만듭니다. 지문이 같아도 실제 내용이 다르면 가져오기를 실패시킵니다.
- 가져오기 결과는 `{ "inserted": 3, "duplicates": 1 }` 형태입니다. `imported_by`는 승인 검사를 통과한 편집자 이름이며 `imported_at`은 DB가 기록합니다.
- 조회 결과는 관측 시각·가져온 시각·ID 역순의 JSON 배열입니다. 기본 500개, 최소 1개, 최대 500개이며 비어 있으면 `[]`입니다. 미확인 선택 항목은 응답에서 생략됩니다.
- 조회는 최신 관측 목록을 반환합니다. 서로 다른 시각·출처의 필드를 합쳐 최신값처럼 보이게 만드는 기능은 없습니다. 화면이 제한된 관측 목록에서 집계한다면 그 범위도 표시해야 합니다.
- 해당 권한을 가진 운영진은 이 저장소의 관측을 함께 봅니다. 별도의 개인별·연맹별 격리는 추가하지 않았습니다.

화면은 최근 500개 관측 범위 안에서 UID별·항목별 최신 값을 합칩니다. 값 아래에 이전 관측 시각을 표시하고 항목별 출처와 시각을 유지합니다. 동일 관측 시각에 서로 다른 값이 저장되면 나중에 가져온 기록을 사용합니다. 가져오기 파일 자체에서는 뒤에 있는 동일 시각 기록을 사용합니다.

JSON 내보내기는 필터에 해당하는 원래 관측 기록을 보존합니다. CSV는 현재 화면의 합쳐진 값과 항목별 `_observed_at`·`_source` 열을 함께 내보냅니다. Excel·Google Sheets에서 CSV를 열 때 `uid` 열은 **텍스트 형식**으로 가져와야 15자리 초과 UID와 앞자리 0을 보존할 수 있습니다. 셀 수식처럼 시작하는 표시 이름은 CSV에서 문자로 처리합니다.

## 로컬 코드 검증

Node.js 22 이상에서 다음으로 테스트합니다. PGlite는 개발용 PostgreSQL 엔진이며 브라우저용 배포 파일에 포함하지 않습니다.

```sh
npm ci
npm test
```

브라우저 흐름은 `npm run test:browser`로 재현합니다. 시스템 Chromium이 없으면 먼저 `npx playwright install chromium`을 실행합니다. 테스트는 네트워크를 차단한 대역 화면에서 실행하며 실제 Supabase·게임 계정에 접속하지 않습니다.

현재 14개 테스트가 데이터 변환·출처 보존·시간 정밀도·누락값·인증값 제거와 SQL의 승인 검사·중복 처리·배치 전체 취소·직접 테이블 접근 거부를 확인합니다. SQL 테스트는 운영 DB와 연결하지 않고 기존 `get_editor_profile`을 명시적인 테스트 대역으로 구성합니다.

## 적용 후 검증

먼저 별도 테스트 프로젝트에서 기존 인증 함수와 동등한 승인 판별을 확인합니다. 운영 데이터로 검증하지 않습니다.

1. 비로그인·익명 세션, 미등록/대기/차단 기기, `device_status` 누락·`null`은 읽기와 쓰기 모두 거부되어야 합니다.
2. 승인 기기라도 `entry`·`*` 권한이 없는 운영진은 거부되고 관리자는 허용되어야 합니다.
3. 같은 관측을 두 번 넣으면 처음만 추가되고 두 번째는 중복이어야 합니다.
4. 두 행 중 뒤 행에 알 수 없는 키·잘못된 UID·시간대 없는 시각·음수·소수·안전 범위 초과 숫자를 각각 넣으면 호출 전체가 취소되어야 합니다.
5. 생략한 수치가 0으로 바뀌지 않고, 기존 시트 명단·인증 데이터가 변하지 않아야 합니다.
6. `anon`·`authenticated`에서 테이블·시퀀스로 직접 접근할 수 없어야 합니다.

마이그레이션은 PGlite PostgreSQL 엔진에서 실행해 위 동작을 검증했습니다. 별도 브라우저 테스트에서는 미리보기 중 무요청, HTML 표시값 처리, 저장 요청의 허용 필드, DB 기능 미설치 안내, 기기 권한 해제 시 화면·메모리 초기화, 모바일 화면을 확인했습니다. 운영 Supabase에 마이그레이션을 적용하거나 실제 계정·운영 DB로 검증하지는 않았습니다. 테스트 대역으로는 운영 환경의 기존 인증 함수와의 호환성을 보장할 수 없으므로, 적용 전 필수 확인 항목을 실제 정의와 대조해야 합니다.
